RND Companion — Linux (x86_64)
==============================

  RND Companion.vst3  ->  ~/.vst3/
  RND Companion.clap  ->  ~/.clap/
  RND Companion.lv2   ->  ~/.lv2/
  RND Companion       ->  run it from anywhere; no host needed

The plain "RND Companion" is the standalone application. It owns the MIDI port
itself, so it is the quickest way to find out whether the device is talking to
you at all, with no host routing in between. If the executable bit did not
survive the download: chmod +x "RND Companion"

Built on Ubuntu 22.04, so it needs glibc 2.35 or newer -- 22.04 and up, Debian
12, Mint 21, Fedora 36. Older than that and it will refuse to load.

The UI is a WebView, so GTK3 and WebKitGTK are a real runtime dependency:

  sudo apt install libgtk-3-0 libwebkit2gtk-4.1-0

A plugin window that opens but stays blank is nearly always this. Two notes:
apt may redirect libgtk-3-0 to libgtk-3-0t64, which is correct and expected;
and WebKitGTK 4.0 no longer exists on 25.04 and later, so 4.1 is the only
option there. Confirmed working on Ubuntu 26.04 with WebKitGTK 2.52.3.

The RND's MIDI port is exclusive: whoever opens it first keeps it. If the
companion reports the device busy, something else already has it -- often a
DAW. Either close that, switch the route to "Host MIDI stream" and let the DAW
carry the traffic, or share the device through a virtual port.

Ardour, Qtractor and Reaper load the VST3; Bitwig the CLAP -- the CLAP is
tested on Linux, the LV2 is not.

On Patchbox OS / MODEP the LV2 is the one to use, with a caveat: that target is
headless, and this plugin reaches for an X display when it is instantiated even
in a console host. X11 is loaded at runtime rather than linked, so a missing
display looks survivable, but nobody has run it on a machine that has none. If
you are the first, say what happens.

Connect the RND over USB before opening; it is found and opened automatically.
